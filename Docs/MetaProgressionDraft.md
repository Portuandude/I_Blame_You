# 런 사이 성장 (메타 진행) 기획 초안

> 2026-11-09 자동 개발 실행에서 작성한 **초안**. 구현은 사람이 후보를 고른 뒤 진행한다. 수치는 모두 가안이다.

## 지금 상태

- 한 런 안의 성장: 레벨업 특성(5갈래 × 20), 정예 구역 유물 상자(3개 중 1개).
- 런이 끝나면 남는 것: 설정, 최고 기록(가장 빠른 클리어 시간, 최고 레벨)뿐 (`SaveData`, PlayerPrefs).
- 그래서 쓰러지면 아무것도 남지 않는다. 로그라이크로서 "다음 판은 조금 더 멀리"라는 동기가 약하다.

## 설계 원칙

1. **두 사람이 함께 쌓는다.** 해금은 A/B 공용 (이 게임의 핵심이 공유 자원이므로). 누가 날려 먹었는지 기록은 남겨 탓할 거리를 준다.
2. **강해지기보다 넓어지기.** 기본 능력치 영구 상승은 작게, 새 선택지(유물·시작 조건)를 여는 쪽을 크게. 그래야 30분 스테이지 난이도 조정이 무너지지 않는다.
3. 기존 저장(`SaveData`)에 키 몇 개만 더하는 수준으로 시작할 수 있어야 한다.

## 후보 A: 마력 결정 + 마법사 탑 (재화형)

- 런 동안 **마력 결정**을 모은다: 적 처치 1, 정예 10, 전투 구역 돌파 3, 봉인문 5, 보스 50. 쓰러져도 모은 결정의 **절반**은 남는다.
- 시작 화면의 **마법사 탑** 메뉴에서 결정을 써서 영구 해금:
  - 새 유물 해금 (유물 상자 후보 풀에 추가, 결정 30~60): 예) "되감기 모래시계"(낭떠러지 낙하 피해 0, 1회), "쌍둥이 반지"(A가 방어막 성공 시 B 마나 +5).
  - 시작 보너스 (각 3단계, 결정 40/80/160): 시작 체력 +5, 시작 마나 +5, 시작 특성 포인트 +1.
  - 편의 (결정 50): 체크포인트에서 특성 다시 찍기.
- 장점: 익숙한 구조(하데스·던그리드), 목표가 분명하다. 단점: 숫자 상승이 쌓이면 난이도가 쉬워짐 → 시작 보너스 상한을 낮게.
- 구현 규모: 중간. `RunStats`에 결정 집계, `SaveData`에 결정·해금 키, 시작 화면 IMGUI 메뉴, `RelicBook` 후보 풀에 해금 조건.

## 후보 B: 도전 과제 해금 (업적형)

- 재화 없이, 조건을 달성하면 해금:
  - "마나를 한 번도 날리지 않고 정예 처치" → 유물 "침착의 부적" 해금
  - "봉인문 두 속성을 한 번에 연속 성공" → 유물 "쌍속성 수정" 해금
  - "체력 10% 이하로 보스 처치" → 시작 화면 "하드 모드"(적 체력 +30%) 해금
  - "A가 마나를 B보다 적게 쓰고 클리어" → 칭호 "양보의 A" (클리어 창 표시, 순수 재미)
- 장점: 플레이 방식을 바꾸게 만든다. A/B 탓하기 기록(누가 마나를 날렸나)과 잘 맞는다. 영구 능력치 상승이 없어 난이도 조정이 쉽다.
- 단점: 처음 몇 판은 아무것도 안 열려서 동기가 약하다 → 쉬운 과제 3~4개를 섞는다.
- 구현 규모: 작음~중간. 조건 검사는 기존 이벤트(`EnemyController.Killed`, `ManaSystem.ManaSpent`, `RunStats`)로 가능.

## 후보 C: 이어지는 마법서 (덱 확장형)

- 쓰러질 때마다 **그 런에서 가장 많이 쓴 속성**의 "숙련도"가 오른다 (불/물/바람/땅/무).
- 숙련도 단계마다 그 속성 마법에 **변형 영창**이 열린다: 예) 불 2단계 = "화염구" 대신 "화염 장막"(앞에 불벽) 영창 추가. B가 영창 창에서 Tab으로 변형을 고른다.
- A쪽은 방어막 숙련도로 "반사 방어막"(같은 속성 투사체 반사) 같은 변형.
- 장점: 이 게임만의 성장 (영창 타이핑이라는 조작과 직결). 강해지기보다 넓어지기 원칙에 가장 잘 맞는다.
- 단점: 변형 마법마다 새 이펙트·밸런스가 필요해 비용이 가장 크다.
- 구현 규모: 큼. `SpellBook`에 변형 정의, 영창 UI 확장, 숙련도 저장.

## 추천

- 바로 시작하기 좋은 것은 **B(도전 과제)** → 이후 **A의 재화**를 얹는 순서. B는 작게 시작해도 의미가 있고, 유물 풀(`RelicBook`)을 늘리는 경로를 그대로 쓴다.
- C는 스테이지 2 이후 콘텐츠가 늘었을 때 다시 검토.

## 사람이 정할 것

1. 후보 A / B / C (또는 B→A 순서) 중 무엇으로 갈지.
2. 쓰러졌을 때 무엇을 얼마나 남길지 (A의 "결정 절반" 같은 규칙).
3. 개발자 모드(치트 가능)에서 얻은 해금을 일반 모드와 나눌지 (최고 기록은 이미 나눠 저장 중).
