## B. 스토리·연출

### B0. ⭐ 숨은 능력치 "선악도"·"인과율" (2026-11-24 사람 결정: 추가한다)

플레이어 캐릭터에게 **화면에 보이지 않는** 능력치 두 개를 넣는다. 기획서에 쓰려면 아래를 정해야 한다.

1. **뜻**: 선악도 = 착한 일/나쁜 일의 누적(예: -100 ~ +100), 인과율 = ? (가안: 운명·우연을 얼마나 비틀었는지. 악신이 "우연"을 이용한 설정(N1)과 이어짐)
2. **올리고 내리는 행동**: 예) 선악도 — 보물 고블린을 놓아주기/잡기, 저주 상자 열기, 마을 NPC 돕기, 항복한 적 살리기 / 인과율 — 쓰러짐·부활 횟수, 운(치명타·유물)에 기댄 정도, 정해진 이벤트를 어긴 횟수
3. **A·B 따로인지 하나인지**: 한 몸이니 하나 / 아루·벨 각자 (각자면 "누구 탓"과 잘 어울림)
4. **무엇에 영향**: 엔딩 분기(B1), 상점 값·NPC 반응, 악신 대사, 등장 이벤트·적, 도시 모습
5. **판을 넘어 남는지**: 한 판 안에서만 / 도시처럼 영구 누적
6. **정말 안 보이게 할지**: 완전 비공개 / 말풍선·색 같은 간접 힌트만
- **추천 (가안)**: 둘 다 판을 넘어 누적되는 영구 값, 선악도는 **A·B 각자**, 인과율은 **한 몸 공용**. 선악도는 엔딩 성향을, 인과율은 "진엔딩 열림"을 정한다. 숫자는 숨기고 악신 말풍선·도시 수정 색으로만 힌트.

| H9 | 저주 상자 무리의 어미 슬라임이 나눈 새끼가 살아 있어도 저주가 풀림 | 의도 불분명 |
| H10 | 기능 테스트 창(F9 유물·F12 장비)이 게임을 안 멈춰 Enter·↑·Space와 겹침 | 구조 판단 필요(BLOCKED) |
| H11 | 호스트가 매 프레임 씬 전체에서 그릴 것을 찾음 (느리면 바꿈) | 베타에서 호스트가 느리면 고침 |

## I. 기술·제작 방식

### I1. ⭐ 정식 아트·사운드
지금 그림·소리는 전부 코드가 만든 임시본이다.
- ① 지금 스타일을 다듬어 그대로 출시 · ② 핵심(캐릭터·보스·UI)만 외주/직접 · ③ 전부 교체
- **추천 ②**: 스팀 캡슐·스크린샷에 보이는 것만 바꿔도 인상이 크게 바뀐다.

### I2. UI를 IMGUI에서 정식 UI(uGUI 또는 UI Toolkit)로 옮길지
IMGUI는 해상도 대응·패드·다국어가 불편하다. 온라인 친구 화면은 IMGUI 기록 방식이라 옮기면 그 부분도 다시 만들어야 한다.
- **추천: 출시 전 한 번 옮김 (스테이지 2 뒤)**.

### I3. 다국어
한국어만 / 한국어 + 영어 / + 일본어·중국어. **추천: 한국어 + 영어** (스팀 판매의 대부분).

### I4. 빠진 .meta 처리
오래된 `.cs` 20여 개·옛 이펙트 PNG 132개의 `.meta`가 저장소에 없다. **추천: 사람 PC에서 생긴 .meta를 GitHub Desktop으로 커밋** (클라우드에서 만들면 PC와 GUID가 달라 깨짐).

### I5. 씬 구조
