# handoff — 긴 세션을 끊고 새 세션으로 넘기기

대화가 길어질수록 매 요청마다 앞의 대화 전체를 다시 읽으므로 토큰이 빠르게 늘어난다. 아래 중 하나면 지금 작업을 마무리하고 넘긴다.

- 세션에 "이전 대화가 요약되어 이어진다"는 안내가 한 번이라도 나왔다 (컨텍스트 압축이 일어남)
- 이번 세션에서 백로그 작업을 6개 넘게 끝냈다
- 같은 큰 파일을 여러 번 다시 읽고 있다

## 넘기는 절차

1. 진행 중인 작업을 커밋 가능한 지점까지 끝낸다 (반쯤 된 코드는 커밋하지 말고 `HANDOFF.md`에 설명만).
2. `Docs/AutoDev/HANDOFF.md`를 아래 틀로 **덮어쓴다** (기록은 git에 남는다). 30줄 안쪽으로.
3. `LOG.md` 이번 실행 항목을 갱신하고 둘 다 커밋·푸시한다 (`Docs/AutoDev: 인수인계 ...`).
4. 자동 개발 실행이면 **사용량을 남기지 않게** 바로 새 실행으로 넘긴다 (2026-11-12 사람 지시: 실행마다 사용량은 다 쓴다):
   `mcp__claude-code-remote__fire_trigger`로 자동 개발 루틴 `trig_01GDVtCSEQ9pwVsne3iFe41Z`를 실행하고, 성공하면 지금 세션은 곧바로 끝낸다 (겹치지 않게).
   fire가 실패하거나 도구가 없으면 **끝내지 말고** 이 세션에서 다음 백로그 작업을 계속한다.

```markdown
# 인수인계 (YYYY-MM-DD HH:MM UTC)

- 브랜치/PR: claude/... → #번호 (상태: CI 대기/머지됨/실패)
- 하던 작업: BACKLOG의 "…" — 끝난 부분 / 남은 부분
- 바로 다음 할 일: 1) … 2) …
- 건드린 파일: 경로 몇 개 (다시 탐색하지 않게)
- 알아낸 것: 함정·결정·수치 (코드나 문서에 아직 없는 것만)
- 환경 메모: 예) mono 설치 필요 → editmode-tests 스킬
```

## 받는 절차 (새 세션 시작 때)

`Docs/AutoDev/HANDOFF.md`가 "없음"이 아니면 백로그보다 먼저 읽고 "바로 다음 할 일"부터 한다.
다 이어받았으면 파일 내용을 `없음`으로 덮어쓰고 커밋한다.
